# 管理者権限・管理者管理（SQLite版）

対象は `main/` のみです。`neon_version/` は変更していません。

## 実装内容

- `admin.role` に `super_admin` / `admin` を保存します。各リクエストでDBの権限と削除状態を確認し、セッション中のIDだけで権限を判断しません。
- 既存サイドバーに最上位管理者のみ「管理者管理」1項目を表示します。一覧の上の「管理者追加」ボタンから追加画面を開けます。一般管理者は既存の管理機能を利用できます。
- `/admin/administrators` は一覧、`/new` は追加です。すべて最上位管理者専用です。追加・削除POSTもDBで権限を再確認します。
- Web追加は手動ID・パスワードのみを入力し、必ず `admin` になります。管理者名・画像・紹介文は本人が「管理者情報」で設定します。IDは1〜128文字、管理者名は1〜100文字、パスワードは12文字以上かつUTF-8で72バイト以内です。パスワードは既存と同じbcryptでハッシュ化します。
- `create_admin.py` の新規作成は `super_admin` です。既存のID・パスワード入力方式を維持し、管理者名は空欄で作成し、本人がログイン後に設定します。既存IDへの上書きや再昇格は行いません。
- 削除は確認ダイアログ付きの論理削除です。最上位管理者は削除できません。今後の有効なメンター予約（当日の未終了予約を含む）があれば拒否します。
- 削除後はログインと既存セッションを無効にし、メンターを非公開にします。予約受付側も削除状態を確認します。工作室の予約可能枠は履歴として残し、新しい予約の定員計算から除外します。
- 過去の予約・通知・メンター情報・操作履歴・パスワードハッシュを保持し、削除済みIDも再利用できません。
- 追加・削除にはCSRF対策を適用し、SQLiteの書き込みロック内で権限・重複・予約の確認と更新を行います。

## 管理者情報の統合とパスワード変更

- サイドバーの「大学生メンター情報」は「管理者情報」に変更しました。URLは `/admin/profile` です。旧URLは互換用に同じ本人専用ページとして維持します。
- 各管理者が自分の名前・画像・紹介文・メンター公開設定を編集します。対象IDはセッションから取得し、フォームで他のIDを指定しても変更対象にしません。他の管理者のプロフィール編集機能はありません。
- 既存の `mentor_profile` を共通プロフィールの保存先として維持し、管理者名と表示名は同一トランザクションで更新します。予約・カレンダー・管理者一覧に共通の名前が表示されます。
- 「生徒にメンターとして表示する」は維持します。非公開ならメンター一覧・予約受付の対象になりません。
- 現在のパスワード、新しいパスワード、確認用入力で本人のパスワードを変更できます。CSRFとDBでの本人確認を行います。変更後は全セッションを無効にし、新しいパスワードで再ログインします。
- `admin.session_version` を追加し、パスワード変更時に加算します。各リクエストでDBの値とセッションの値を照合します。
- `admin_profile_v1` の移行を記録し、既存メンター名の引き継ぎを一度だけ行います。名前だけある既存管理者のプロフィールは非公開で作成します。移行前バックアップとトランザクションを使用します。
- 予約時に保存された通知本文や外部Googleカレンダーの過去イベントは書き換えません。

## DB移行

アプリ起動時または `create_admin.py` 実行時に、再実行可能な移行を行います。別途初期化コマンドを実行する必要はありません。

- `admin` に `name`、`role`、`deleted_at` を追加します。テーブルの削除・作り直しは行いません。
- 初回のみ `26A001` を `super_admin` とします。その他の既存管理者は既定の `admin` となります。
- `schema_migration` に `admin_roles_v1` を記録し、再実行時の再昇格を防ぎます。
- 初回移行前にSQLiteのbackup APIで `database/database.db.<移行名>.<日時>.bak` を保存します（移行名は `admin_roles_v1` または `admin_profile_v1`）。バックアップには認証情報が含まれるため、DBと同様に保管してください。既存のGit除外設定が適用されます。
- 今回確認したローカルDBでは `26A001` の `super_admin` を確認済みです。再実行前後の全テーブルの行一致と `PRAGMA integrity_check` の `ok` を確認しました。検証時点のスナップショットも `database/*.admin_roles_verified.*.bak` に保存しました。
- 管理者情報の統合移行では、既存メンターの表示名を管理者名として引き継ぎます。画像・紹介文・公開状態は保持します。名前が未設定の新規管理者は一覧で「未登録」と表示します。

## セッション

コード内の固定署名キーを廃止しました。`SESSION_SECRET`（32文字以上）があれば使用し、なければ `database/.session_secret` にランダムキーを生成・保存します。このファイルはGitから除外します。再起動してもキーは維持されます。

変更の初回適用時は全ユーザーの再ログインが必要です。キーを削除・変更すると再びセッションが無効になります。

## 変更ファイル

- `main.py`：移行、DBでの認証・権限再確認、署名キー、サイドバー用コンテキスト、工作室予約枠の除外。
- `admin_management.py`：移行・バックアップ・入力検証・最上位管理者専用ルート・本人のパスワード変更。
- `create_admin.py`：CLIでの最上位管理者作成。
- `mentor_reservations.py`：削除済み管理者の表示・新規予約受付を停止。
- `templates/admin/base.html`、`templates/admin/administrators.html`：既存サイドバーと管理者管理ページ。
- `templates/admin/mentor_profile.html`、`templates/admin/mypage.html`、`templates/admin/login.html`：本人の共通プロフィール・パスワード変更・ログイン案内。
- `static/admin/admin.css`、`static/admin/administrators.css`：表示スタイル。
- `database/.gitignore`：署名キーの除外。ローカルの `database.db` は移行済みです。
- `tests/test_admin_management.py`：権限・認証・CSRF・追加・削除・移行のテスト。
- `tests/test_notifications.py`、`tests/test_studies.py`、`tests/test_mentor_reservations.py`：新スキーマに合わせた既存テストのDB準備。

## 動作確認

Pythonの全105テストを一時DBのコピーで実行し、すべて通過しました。実際のASGIリクエストによるログイン、一般管理者のGET/POST拒否、最上位管理者の一覧・追加・削除、CSRF、入力検証、重複ID、権限の不正指定、削除後の既存セッション無効化、予約と履歴の保持、移行バックアップと再実行を確認しました。
